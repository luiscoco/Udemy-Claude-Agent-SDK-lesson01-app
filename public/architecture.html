Before the first message

Install the dependencies, set the key in the launching shell, and choose the working directory. The SDK starts a local runtime; Claude inference happens through the configured provider. No Managed Agents agent or environment IDs are required.

02

2. Check inherited key and input

Browser + host → Browser + host. The launching process must inherit a key. The browser host also validates the prompt before starting the runtime.

Source: src/server.ts · lines 17–17

Selected source excerpt; surrounding context may be omitted.

const ready = () => Boolean(process.env.ANTHROPIC_API_KEY && !process.env.ANTHROPIC_API_KEY.startsWith("your_"));

How this code explains step 2

The server checks that its launching environment contains a non-placeholder key before accepting the request. The actual key is never returned to the page.

03

3. query(prompt, options); cwd set

Browser + host → Agent SDK. The host creates one query object. Its options select sample-workspace as cwd and make only Glob available.

Source: src/agent.ts · lines 69–72

Selected source excerpt; surrounding context may be omitted.

const conversation = query({
  prompt,
  options: lessonOptions(abortController),
});

How this code explains step 3

One query receives the prompt and lessonOptions. Those options fix cwd to sample-workspace; the SDK manages subsequent interactions.

04

4. Send prompt and Glob tool definition

Agent SDK → Claude API. The runtime sends the task and the Glob tool definition to the model. It does not supply the browser reference list as an answer.

Source: src/agent.ts · lines 16–19

Selected source excerpt; surrounding context may be omitted.

model: MODEL,
cwd: WORKSPACE,
tools: ["Glob"],
allowedTools: ["Glob"],

How this code explains step 4

This is the application configuration for the SDK-managed request: choose the model and working directory, and expose only Glob. The SDK performs the model API transport internally.

05

5. Request Glob file discovery

Claude API → Agent SDK. The model chooses Glob. An assistant tool_use block exposes the requested tool and pattern as observable progress.

Source: src/agent.ts · lines 48–51

Selected source excerpt; surrounding context may be omitted.

if (block.type === "tool_use") {
  const input = block.input as { pattern?: string };
  events.push({ type: "tool", name: block.name, pattern: input.pattern || "" });
}

How this code explains step 5

The observer detects the actual tool_use block and records its tool name and pattern. Claude chooses the request; this code observes it rather than fabricating a model response.

6. Run Glob in sample-workspace

Agent SDK → Demo folder. The SDK executes the built-in listing tool locally. This does not require a Bash command or a Read tool.

Source: src/agent.ts · lines 17–19

Selected source excerpt; surrounding context may be omitted.

cwd: WORKSPACE,
tools: ["Glob"],

How this code explains step 6

The cwd and tools properties establish the boundary for the built-in Glob operation. The SDK executes Glob; there is no custom Glob implementation in this app.

07

7. Return matching file paths

Demo folder → Agent SDK. The local tool returns the file paths it actually found, including the nested src/hello.ts file.

Source: src/agent.ts · lines 74–79

Selected source excerpt; surrounding context may be omitted.

for await (const message of conversation) {
  for (const event of projectMessage(message)) {
    if (event.type === "result") gotResult = true;
    emit(event);
  }
}

How this code explains step 7

The SDK collects the actual file-path result internally. This consuming loop receives the SDK stream and projects selected message types; this app does not separately forward raw user/tool_result content.

08

8. Send the tool result to Claude

Agent SDK → Claude API. The SDK handles the next model interaction with the tool result. The host does not implement a manual Messages API loop.

Source: src/agent.ts · lines 74–79

Selected source excerpt; surrounding context may be omitted.

for await (const message of conversation) {
  for (const event of projectMessage(message)) {
    if (event.type === "result") gotResult = true;
    emit(event);
  }
}

How this code explains step 8

The SDK feeds Glob output into its next model interaction while the host consumes the same query iterator. The host does not manually send tool feedback or call query again for each message.

09

9. Produce the final answer

Claude API → Agent SDK. Claude produces a human-readable answer informed by the returned paths. The wording may vary across runs.

Source: src/agent.ts · lines 47–47

Selected source excerpt; surrounding context may be omitted.

if (block.type === "text") events.push({ type: "answer", text: block.text });

How this code explains step 9

Text blocks from the actual assistant message become answer events. These statements observe the model answer after the SDK has handled discovery.

10. Yield tool, text and result messages

Agent SDK → Browser + host. The same async iterator yields progress and a final SDK result. One query call can include multiple model turns.

Source: src/agent.ts · lines 74–79

Selected source excerpt; surrounding context may be omitted.

for await (const message of conversation) {
  for (const event of projectMessage(message)) {
    if (event.type === "result") gotResult = true;
    emit(event);
  }
}

How this code explains step 10

The async loop forwards selected tool, text and final-result events. gotResult records a final outcome independently from intermediate assistant content.

11. Print results or render safe text

Browser + host → Browser + host. The terminal prints selected output with console.log; the browser renders projected events using textContent.

Source: src/sample.ts · lines 12–17

Selected source excerpt; surrounding context may be omitted.

if (message.type === "assistant") {
  for (const block of message.message.content) {
    if (block.type === "text") console.log(block.text);
    if (block.type === "tool_use") console.log(`Tool: ${block.name}`);
  }
}

How this code explains step 11

The terminal sample prints assistant text and tool names. The browser offers the corresponding event display; both consume SDK output.

12

12. Compare files; check final status

Browser + host → Student. Compare the named files with the demo folder and inspect the final result status. Text or a tool call alone does not establish completion.

Source: src/client.ts · lines 33–35

Selected source excerpt; surrounding context may be omitted.

finalResult = true; $("status").textContent = data.status === "success" ? "Success" : data.status;
$("cost").textContent = "$" + data.costUsd.toFixed(4); $("turns").textContent = String(data.turns); $("session").textContent = data.sessionId;
if (!answer || data.status !== "success") $("answer").textContent = data.text;

How this code explains step 12

The browser updates final status, estimated cost, turn count and session ID from the actual result. Students compare the answer with the separately labelled host file list.

One query call can contain a model → tool → model round trip. The browser does not provide a prewritten answer. Its host reference list is separate from the agent’s discovery. Only Glob is available, and cwd is a working-directory choice rather than an operating-system sandbox.
